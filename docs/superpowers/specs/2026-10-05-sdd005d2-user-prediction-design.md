# SDD-005D2 用户五日预测与本人记录

## 意图与范围

用户要求继续下一业务，沿用已确认的五日Transformer、已审核发布模型、13业务/五服务/两角色。用户在行情页进入预测页，选择受支持模型，查看生成与失败状态，成功五点不可改写，历史仅本人可见并可隐藏。AI解释与事后评价独立，本批未接入时明确未接通，不显示假区间或错误准确率。

## 方案

1. 采用既有MS-03同步编排，不新增独立后台队列；后台训练仍归MS-04。相对于新建预测消息队列，直接同步更适合现有单槽与五日推理，代价是首次输入准备最长约两分钟。Nginx与网关仅预测请求独立延长超时，前端等待中可查询同请求记录。
2. POST /api/v1/predictions {operationId UUID,modelId UUID,instrumentId,horizon 5}；本人GET /predictions?page=1、GET /predictions/{id}、POST /predictions/{id}/hide。角色身份仅来自MS-01会话；POST Origin/CSRF与既有策略一致。客户端不得提交ownerId、价格或发布状态。
3. MS-03独立forecast_request表保存请求、不可变模型描述、状态、到期时间、完整成功快照或受控失败；唯一(user_id,operation_id)，同键参数冲突409。一名用户同时一个RUNNING，由同库用户guard锁检查；重复请求读取同一记录，不重新计算。成功只可由RUNNING且未到期更新一次；到期RUNNING变FAILED/PREDICTION_INTERRUPTED，旧执行不得回写。重启后首次查询/提交检查到期，未承诺自动重执行。隐藏不删除快照，ADMIN也只能普通接口查本人记录。
4. 执行之前在本库核对模型PUBLISHED与60/5、股票适用范围，固定manifest/checkpoint/revision。先读取MS-02当前输入；缺输入时读RAW末60日→Python真实forecast-collect→MS-02严格发布→读取固定inputID。只有明确缺输入时准备，失联/陈旧不可误当缺输入。再次默认输入检查当前头一致。调用D1 infer固定五字段；成功必须回显全部身份、RAW/input/hash、FRESH、五日递增、正式标志和原点/价格，核对原manifest/checkpoint及publicationRevision，保存固定原输入与数值。执行期间新版本不替换；首次publication返回revision变化则失败重新发起。
5. 业务HTTP固定URL、禁redirect、无共享Cookie、有限体积131072、完整响应deadline：行情10秒/采集35秒/推理50秒；失败安全编码，不暴露服务响应/凭据。原数据权重及D1数学计算不变。跨服务准备发布重复候选由既有hash/operation保障，当前RAW头发生变化则拒绝旧输入新预测。
6. UI沿用白底、蓝色操作、可访问标签，模型与五日固定时期明确，错误/空模型/处理中/成功各自可见。显示原点、五日参考价格曲线和明细、模型与输入版本、误差区间未校准、AI解释未接通、事后验证未接通。历史分页、详情、隐藏；请求键在本机sessionStorage按当前账号保存，网络未知不生成新键，先查询或复用原POST；退出/切换账号不得串记录。

## 验收

真实隔离MySQL：并发同请求一次、参数冲突、本人边界、隐藏不删除、到期旧写拒绝、重建实例历史保留。MockMvc：未登录/伪身份拒绝、Origin/CSRF、未知字段、普通账号可本人请求，管理员不能越权。真实本机HTTP fixture：完整输入准备及成功五点、缺行情/陈旧/发布失败/模型变更/错版本/依赖停顿无成功。前端行为测试：空模型拒绝、推荐选择、网络重放原键、查询/详情/隐藏、错误无曲线；严格构建。现用三个候选PENDING，真实部署只核验拒绝，正向fixture为协议测试，不自动发布或声称准确性。

## Rulings

沿用用户自治/固定目录/当前codex分支，先规格计划自审，再作者执行/唯一最终独立审查，不重复请求常规授权；代价是若方案不合意需调整。同步请求记录不是新的后台调度队列，首次等待较长，后台训练范围不减。事后行情验证、MaaS解释与校准区间后续分步，界面明确未接通，本批不宣称FR05/06全部完成。未发布候选不自动发布，现用正向验收需要管理员真实审阅。
