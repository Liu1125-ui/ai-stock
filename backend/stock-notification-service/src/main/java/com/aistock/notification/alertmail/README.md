# 预警邮件投递

作用：独立保存预警渠道决策、固定依据密文及本人投递状态，不复用注册验证码命令。

实现方法：触发、站内消息、渠道决策同通知库事务提交；owner guard→delivery→rule锁顺序。CHECKING核验当前账号/已验证邮箱及账号、规则、偏好修订；提交SENDING后在事务外调用SMTP。SMTP明确接受记SENT，不代表实际收到；提交结果不确定或SENDING租约过期记UNKNOWN且不自动重发。仅明确未接受可按最大次数/TTL退避重试。

发送默认关闭。独立ticker仍执行最多100条的安全维护：过期SENDING→UNKNOWN、过期待发→EXPIRED；不领取新的发送任务，不调用账号或SMTP。数据库准备故障保留可恢复CHECKING，正文校验故障使用专用异常。公开状态接口仅本人可读，不返回地址、密文或身份锚点，读取不发送或改状态。

真实开启前需明确收件人和数量授权，并等待符合规则的新自然触发，不补发旧消息或伪造行情。参见docs/verification-sdd006c.md。
