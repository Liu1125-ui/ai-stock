# 行情服务迁移

Flyway 管理行情服务自有表。V1 建立带 `demo_only` 标识的证券基础资料表，V2 插入一条仅用于联调的虚构样本；不构成真实行情。生产环境通过独立数据库账号执行迁移，后续配置单独迁移账号。

V3/V4：不可变行情版本与持续更新执行回执；V5：独立预测输入、配对转换、未来日历与幂等回执；V6：按真实来源扩展后复权close到28,12。已应用迁移不编辑校验和，通过后续版本作兼容变更。

V7：独立realization证据版本与操作回执。LONGTEXT+JSON_VALID保留十进制字符串与固定证据，不修改既有RAW行情版本或预测输入。内容哈希去重，过期/来源失败不创建版本。
V11：独立比较历史证据与幂等发布记录，仅关联本库RAW。

V15：分离内容发布事实与新使用许可，新增生命周期、使用bundle/明细、动作/事件五表；仅回填已有AVAILABLE的baostock/RAW版本。owner身份由bundle外键规范化，generation唯一键和本库FK约束避免重复/孤儿凭据。不改变原行情头/日线/预测输入；代码接入全部消费者前不对生产执行此迁移或开放动作。

V16：内部USE/ACTION命令身份锁，解决首次登记没有bundle行可锁的问题；无新业务数据或公共接口。USE锁按owner/operation/generation串行，已绑定用途不能改变。V15迁移专项固定验证到V15，新仓储集成测试通过夹具迁移到最新V16；仅测试环境执行。

V17：bundle追加可空selector_json保留原选择，新增use_request传输幂等回执表；旧selector为空只能在相同selectorHash的原登记重放时补齐。新回执引用bundle，测试清理先删request再删bundle。未在业务库执行。

V18给比较刷新receipt增加fencing及本地使用记录；只新增列/表，不更改旧内容、头或证据。

V19新增市场预警使用记录/原请求JSON与父fencing。旧行不回填伪请求或时间；迁移不改历史证据/行情头。
