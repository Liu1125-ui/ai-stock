# 独立预警任务
作用：持久化预警准备/评价任务，恢复未知回执，避免同规则重复任务绕过在途操作。
实现：MS-04本库任务和attempt；按股票、RAW版本、交易日共享证据准备；有限重试与租约恢复。通过内部接口访问MS-02/MS-05，不跨库。默认关闭，扫描代码已接入，尚未部署或接入公开消息页。

任务先保存操作ID，再调用HTTP；不确定结果先查原回执。每阶段至多3次明确失败尝试，60/120秒退避，120秒租约。共享证据缓存5分钟，未决源工作不按缓存超时重开。HTTP连接2秒、执行30秒、回执10秒、响应128KiB；由AlertJobConfiguration读取内部服务地址/令牌，不在日志写令牌。AlertJobWorker默认关闭，Task4另接扫描计划后再按Task7部署验收。此目录不持有其他服务数据库连接。

## 扫描与日历

AlertScanPlan每tick只处理一页（默认50条）：先检查独立日历，再优先推进到期的完整规则补查，其余tick消费独立RAW修订事件。每小时重新从第一页检查启用规则；事件只提供股票线索，实际任务使用最新HEAD及最新应到期交易日。每页按股票共享边界读取，当前股票范围可配置，默认沿用三股。行情滞后/边界缺失不生成旧日任务，其余股票可继续检查；最近页原因保存在游标。MS-05执行时再次核验规则、账号与最新边界。

AlertScanRepository通过游标版本比较和行锁控制竞争；页游标和本页任务在同库事务中提交，队列预算默认1000条活动任务，容量不足暂停该页，不越过未处理页。未决任务仍由Task3的active_key保护，下一轮不能绕过；新RAW或规则修订另作核验。

V6仅新增本库alert_scan_cursor、alert_calendar_refresh、alert_scan_budget，不更改V5或原预测验证游标。日历每天成功刷新一次，失败5分钟后重用同一操作ID重试，刷新租约120秒。查询覆盖截止日前365天，检查完整自然日、来源哈希及7天时效；固定北京时间20点策略与当前MS-02/MS-05一致，更改需协调三服务。日历读取无法核验时保存CALENDAR_SNAPSHOT_UNVERIFIED并暂停，恢复后清除该诊断，不改变刷新租约/节奏。

环境模板及Compose默认ALERT_PLAN_ENABLED=false、ALERT_WORKER_ENABLED=false。本阶段只验证配置与隔离数据库；最终部署、开启及真实触发验收在Task7，邮件仍属于C阶段。
