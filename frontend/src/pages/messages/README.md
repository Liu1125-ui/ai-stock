# 消息页面

## 作用
MessagesPage提供本人全部/未读消息、分页、单条和有界批量已读。MessageEvidence展示触发时的固定条件、阈值、价格/复权口径及可展开证据。TriggerHistoryPanel供规则页复用；RecentMessages在首页显示最近三条和查看全部入口。

## 实现方法
复用api/messages.ts与既有会话/CSRF请求封装，金额和计算源值保留字符串；百分比仅在展示时四舍五入。页面请求使用账号代次和请求序号，拒绝旧筛选或前账号响应；失败保留已有数据，账号切换立即清空。批量最多50个唯一可见ID，写请求期间禁用操作；已读使用返回的首次readAt，不自行覆盖时间。

导航由Pinia inbox存储读取未读数，在登录、进入消息页面、手动刷新及已读后更新。读取失败为未知，不显示虚假的0；没有高频轮询。401沿用原会话失效流程。首页不新增摘要接口，使用listMessages(1,3,false)。规则历史仅取固定快照；空记录不等于从未满足条件，不伪造最近检查状态、当前触发或邮件成功。

## 当前范围
不发送邮件、不调用MaaS、不生成预测、不创建预警触发记录。页面实现不等于业务容器已部署；全链路与真实触发验收在Task7进行。
